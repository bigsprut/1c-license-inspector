## Что работает (проверено)

1. **8.2** — консоль через MMC 2.0 **в процессе программы** (не helper!):
   `MMC20.Application` → `Load("C:\Program Files\1cv82\common\1CV8 Servers (x86-64).msc")`
   → поиск узлов «Рабочие процессы»/«Сеансы» (исключая путь «Информационные базы»!)
   → `View.ExportList(file, 3)` (Unicode TSV).
   Разрядность — как у рабочей консоли: на x64 — 64-битная MMC, иначе дерево пустое.
   Автосбор встроен в сканирование (`src/AutoConsole82.cs`).
2. **8.3** — `rac`: **новый синтаксис с 8.3.24+**:
   `rac session list --cluster=<uuid> --licenses --cluster-user="…" --cluster-pwd="…" localhost:1545`
   (режим и команда первыми, адрес **в конце**). Старый синтаксис — фолбэк.
   `cluster list` — **без** прав (с `--cluster-user` даёт «Ошибка разбора параметра»).
   Вывод `rac` — OEM cp866, читать байтами и декодировать по OEM.
3. Программные лицензии `.lic` 8.3 — текстовые, PIN/места/привязка читаются.
4. Автовыгрузка результатов на диск локальной машины через RDP-редирект:
   `\\tsclient\D\work\Learn\DSHarness\1CCommon\drop` (`src/AutoDrop.cs`):
   `report-*.html`, `digest-*.txt`, `latest-digest.txt`, `latest-rac-cluster.txt`,
   `latest-rac-sessions.txt`, `latest.log`. Fallback — `C:\ProgramData\1C-License-Inspector\drop`.
   **Агент читает оттуда сам** — Сергея не просить искать файлы.
5. Кнопка «Отчёт» копирует полный дайджест в буфер (без диалогов).
   CLI: `/digest:<file>`, `/report:<file>`, `/rac:<path>`, `/clusteruser:`, `/clusterpwd:`,
   `/racprobe[:<file>]`, `/silent`. `/racprobe` без пути пишет отчёт прямо в `drop`.

## Блокер 8.3 — разобран 27.11.2026 (осталось подтвердить на ALL)

**8.3-сервер ALL** (Windows Server 2016, 8.3.27.2342, ras на `localhost:1545`,
кластер `365a0d3e-0672-4ec8-b45f-2d5c8c5609b7`).

Что выяснено из старых дампов `drop\`:

- аргументы приложение передаёт правильно (ошибка разбора `--cluster-user=` была только
  в 1.5.25 и исправлена) — дело не в кавычках;
- **до ~18:30 администраторов в кластере не было**: `rac session list` без прав отдавал
  `rc=0` и пустой вывод. После того как Сергей создал администратора, тот же вызов отвечает
  `rc=-1 «Администратор кластера не аутентифицирован»` — значит смена режима произошла
  именно из-за появления администраторов, а сам rac/ras работает;
- в прогоне 18:59 логин `serg_clad` дал `rc=0` **без ошибки**, но с пустым списком. То есть
  этот логин, скорее всего, **аутентифицируется**, а сеансов в тот момент не было.

Две ошибки в самом приложении (исправлены в 1.5.28):

1. Успешный ответ с пустым stdout (сеансов нет) **затирался** ошибкой следующей попытки —
   на экран выходило «не аутентифицирован», хотя вход прошёл. Теперь любой `rc=0` без
   ошибки считается успехом, перебор прекращается.
2. Не было автоматического подбора логина: теперь, если указанный логин не подошёл,
   приложение читает `rac cluster admin list` и пробует **имена администраторов кластера**
   с тем же паролем (пропуская тех, у кого нет способа `pwd`).

Что добавила документация (и чего не хватало раньше) — версия 1.5.29:

- «Руководство администратора. Клиент-серверный вариант»: **версии кластера, ras и rac должны
  совпадать**. На ALL установлено шесть платформ 8.3, поэтому rac от самой новой версии мог
  отвечать успешно и **пусто**. Теперь приложение берёт rac из версии работающего `ras.exe`/агента,
  а если данных нет — перебирает остальные платформы и запоминает рабочую.
- `--licenses` даёт лишь дополнительные сведения: если кластер их не отдаёт, ответ бывает `rc=0`
  и пустой. Теперь запрос повторяется **без** `--licenses`, и это видно в «примечании».
- Пока администраторов кластера нет, вход вообще не требуется — логин вводить не нужно.

Что делать на ALL (версия 1.5.29):

1. Запустить инспектор, вкладка «Использование» → «Опросить» (логин и пароль оставить пустыми,
   если администраторы не созданы).
2. Если сеансы не появились — «Диагностика» → **«Полная диагностика rac»**: файл
   `racprobe-*.txt` и `latest-racprobe.txt` лягут в `drop`. В «ИТОГЕ» будет список администраторов с
   их способами входа (`pwd`/`os`/`publickey`), раздел «Версия rac: какая платформа видит кластер»
   и точные тексты ошибок.
3. Если у нужного администратора нет `pwd` (только `os`/`publickey`) — вход по паролю
   невозможен: либо пересоздать администратора с паролем в консоли, либо использовать
   `--cluster-key=<файл приватного ключа>` (в 8.3.27 ключ задаётся при регистрации
   администратора с `--auth=publickey --publickey=…`).

## Грабли (не наступать снова)

- Правки кириллицы в `.cs` — **только** `edit`/`write`; `-replace` из PowerShell не находит.
- `.NET 4.0`: нет `Marshal.StructureToPtr<T>` (только `(object)`) , нет `StandardOutputEncoding`.
- `LooksLikeError` не должен искать слово «error» в stdout: поле `errors-count-threshold`
  ломало разбор (исправлено 1.5.18).
- Узлы «Сеансы» в 8.2 дублируются (под инфобазой и на уровне кластера) — брать кластерный.
- Секрет-скан `publish.ps1` ловит строку с присваиванием паролю — в коде использовать `pwd`.
- В `docs/` нельзя хранить внутренние адреса, имена тестовых серверов и номера лицензий:
  репозиторий публичный, скан `publish.ps1` на них падает. Адреса и доступы — только
  в приватных файлах вне репозитория.
- WinForms: без автмасштаба, шрифты в пикселях, страницы по требованию (см. SKILL.md).
- `rc=0` и пустой stdout у `rac session list` — это **успех** («сеансов нет»), а не сбой:
  нельзя затирать его ошибкой следующей попытки (было в 1.5.27 и раньше).
- Запуск exe из PowerShell: `& exe` для GUI-приложения **не ждёт** окончания (файла ещё нет),
  а `Start-Process -Wait` в этой среде подвисал. Надёжно: `cmd /c "\"build\1C-License-Inspector.exe\" /args..."`.
- Заглушка rac для автотестов без кластера: `tools\racstub.cs` →
  `csc /out:build\racstub.exe /codepage:65001 tools\racstub.cs`, затем
  `/rac:build\racstub.exe /clusteruser:Администратор /clusterpwd:<любой>` — эмулирует
  анонимный `cluster admin list` и вход только логином `rac_admin`.
