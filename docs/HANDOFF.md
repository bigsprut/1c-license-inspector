**Настоящая причина** (подтверждена прогоном, а не догадками):

2. Дополнительно: версии кластера, `ras` и `rac` должны совпадать (руководство администратора 1С,

**Лечение (1.5.29–1.5.30):** запрос сеансов с `--licenses` **и без него**; rac подбирается по версии
работающего `ras.exe`/агента, затем перебором остальных платформ; сведения о лицензиях добираются
по каждому сеансу через `rac session info --session=<uuid> --licenses`.

## Грабли (не наступать снова)

- Правки кириллицы в `.cs` — **только** `edit`/`write`; `-replace` из PowerShell не находит.
- `.NET 4.0`: нет `Marshal.StructureToPtr<T>` (только `(object)`) , нет `StandardOutputEncoding`.
- `LooksLikeError` не должен искать слово «error» в stdout: поле `errors-count-threshold`
  ломало разбор (исправлено 1.5.18).
- Узлы «Сеансы» в 8.2 дублируются (под инфобазой и на уровне кластера) — брать кластерный.
- Секрет-скан `publish.ps1` ловит строку с присваиванием паролю — в коде использовать `pwd`.
- В `docs/` нельзя хранить внутренние адреса, имена тестовых серверов и номера лицензий:
  репозиторий публичный, скан `publish.ps1` на них падает. Адреса и доступы — только
  в приватных файлах вне репозитория.
- WinForms: без автмасштаба, шрифты в пикселях, страницы по требованию (см. SKILL.md).
- **Скрытие столбца под текущей ячейкой DataGridView** бросает `InvalidOperationException`
  «Текущую ячейку нельзя сделать невидимой» (проявилось в 1.5.33 при скрытии пустых столбцов).
  Правило: после `HideEmptyColumns` уводить `CurrentCell` на первый **видимый** столбец
  (`FirstVisibleColumnIndex`) или снимать его; ставить `Cells[0]` нельзя.
- Регрессия на это проверяется заглушкой: `RACSTUB_DROP=infobase` убирает поле из ответа
  `rac session list`, первый столбец становится пустым и скрывается — старый билд висит,
  новый строит страницу.
- **8.2: файлы `*.lic` зашифрованы.** PIN, редакцию и места снаружи прочитать нельзя (только сама
  платформа или `ring`), поэтому в таблице файлов у 8.2 остаётся «—». Серия, места и занятость
  видны в **консоли администрирования** — с 1.5.40 приложение сводит их в отдельный раздел
  «Лицензии по данным консоли 8.2» на вкладке «Программные лицензии» (PIN · мест · занято ·
  свободно · файл) и в дайджест. Если у файла 8.2 всё-таки известен путь (`LicenseFile` из
  консоли), счётчик «Использ.» привязывается по имени файла.
- **Серверную лицензию занимает сервер, а не сеансы** (1.5.39): `LicenseFileInfo.IsServerLicense`
  определяется по типу/продукту («сервер»), и для неё считается не число сеансов, а работает ли
  агент (ragent/rphost/rmngr из `r.Processes`). В таблице — «сервером» / «—», в сводке —
  «занята работающим сервером (rphost/rmngr)» либо «сервер 1С не запущен, лицензия свободна».
  Сеансы для серверной лицензии не считаются: `issued-by-server: yes` означает, что **клиентская**
  лицензия выдана сервером, и она сопоставляется со своим клиентским файлом.
- **«Использовано» по лицензиям** (1.5.38): в таблице файлов лицензий есть столбец «Использ.»
  — сколько сеансов держат эту лицензию. Считает `CollectLicenses.MatchUsage`: серия из `rac`
  (`123456789`) сопоставляется с рег. номером файла (`123456789O0`) по цифрам; вызывается из
  `Scanner` после сбора сеансов, значение живёт в `LicenseFileInfo.UsedBySessions` (-1 — кластер
  не опрошен). Итог «занято N из M» в сводке тоже считается по нему. В дайджесте — «использовано N».
- **У спящих сеансов лицензии нет по правилам 1С.** Если `hibernate: yes`, сервер освобождает
  клиентскую лицензию, и `session list --licenses` / `session info --licenses` возвращают пусто —
  это не сбой чтения. В таблице с 1.5.37 есть столбец «Состояние» (активен/спит), а в «Лицензии»
  пишется «не выдана (спит)»; в подсказке внизу — сколько таких сеансов.
- **`--licenses` меняет ответ rac.** На ALL `session list --licenses` отдаёт только лицензионную
  часть (нет `infobase`, `started-at`), а без ключа — полные записи сеансов. Основной запрос —
  **без** `--licenses`; лицензии добираются отдельно и переносятся по UUID (1.5.35).
- Лицензионные столбцы берутся из структурных полей (`license-type`, `series`, `max-users-*`),
  а не разбором `short-presentation`; `soft` → «программная», `yes` → «да», для серверной
  лицензии «занято/свободно» не выводим.
- `rc=0` и пустой stdout у `rac session list` — это **успех** («сеансов нет»), а не сбой:
  нельзя затирать его ошибкой следующей попытки (было в 1.5.27 и раньше).
- Запуск exe из PowerShell: `& exe` для GUI-приложения **не ждёт** окончания (файла ещё нет),
  а `Start-Process -Wait` в этой среде подвисал. Надёжно: `cmd /c "\"dist\1C-License-Inspector.exe\" /args..."`.
- Заглушка rac для автотестов без кластера: `tools\racstub.cs` →
  `csc /out:build\racstub.exe /codepage:65001 tools\racstub.cs`, затем
  `/rac:build\racstub.exe /clusteruser:Администратор /clusterpwd:<любой>` — эмулирует
  анонимный `cluster admin list` и вход только логином `rac_admin`.
