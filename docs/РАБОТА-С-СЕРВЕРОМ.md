# Работа с сервером, где открыт только RDP

Короткая инструкция к «обработчику» (`Worker.exe`): зачем он нужен, как включить, как отправить
задание и где забрать ответ. Инструкция по самому приложению — в [README.md](README.md).

## Зачем это

На боевых серверах снаружи открыт **только RDP** (у нас — порты 55200 и 55210). WinRM, WMI и SSH
закрыты, поэтому запустить там команду «по сети» нельзя. Зато пока вы подключены по RDP, сервер
видит вашу папку проекта `\\tsclient\D\work\Learn\DSHarness\1CCommon`.

`Worker.exe` — крошечная программа (15–19 КБ), которая работает **в вашем RDP-сеансе** и служит
мостиком: читает задания из папки `queue\` и складывает ответы в `drop\`.

```
queue\all\<id>.task   →  Worker (на сервере)  →  drop\result-all-<id>.txt
```

- Ничего не устанавливает, служб и задач в планировщике не создаёт, в реестр не пишет.
- Выполняет **только** команды из белого списка (см. ниже).
- **Окно открыто = доступ есть. Окно закрыто = доступа нет.**

## Шаг 1. Включить обработчик

1. Подключитесь к серверу по RDP.
2. Откройте папку проекта на своей машине (в сеансе она видна как `\\tsclient\D\work\Learn\DSHarness\1CCommon`).
3. Запустите:
   - **сервер 2016** — `Обработчик-ALL.cmd` (очередь `all`);
   - **сервер 2003** — `Обработчик-S200.cmd` (очередь `s200`).
4. Появится чёрное окно со строками `Host`, `Project`, `Queue`, `App` и просьбой не закрывать его.
   Свернуть можно, закрывать — значит выключить доступ.

Окно лучше запускать **от администратора**: иначе часть служб и защищённых каталогов может быть
недоступна (программа честно это отметит).

## Шаг 2. Отправить задание

На своей машине, в PowerShell, из папки проекта:

```powershell
.\tools\queue-send.ps1 -Command digest -Server all -TimeoutSec 300
```

- `-Server all` — очередь сервера 2016, `-Server s200` — сервера 2003.
- `-TimeoutSec` — сколько ждать ответа (для `digest` хватает 300, для `racprobe` — 180–240).
- `-NoWait` — отправить и не ждать (ответ потом смотреть в `drop\`).

Скрипт сам создаёт `queue\<сервер>\<id>.task`, ждёт появления `drop\result-<сервер>-<id>.txt`
и печатает ответ на экран.

## Шаг 3. Прочитать ответ

- Если ждали — ответ уже напечатан в консоли.
- Если нет — файл `drop\result-all-<id>.txt` (обычный текст, UTF-8).
- Дайджест (`digest`) дополнительно копируется в `drop\digest-<сервер>-<дата>.txt`,
  а приложение на сервере кладёт свои выгрузки в `%ProgramData%\1C-License-Inspector\drop`.

## Команды

| Команда | Что делает | Ждать |
|---|---|---|
| `noop` | проверка связи, «обработчик на связи» | 30 с |
| `version` | версия сборки, которая лежит в `build\`/`dist\` | 30 с |
| `digest` | полный текстовый отчёт-дайджест: платформы, лицензии, ключи, сеансы, нагрузка, хвост журнала | 300 с |
| `racprobe` | полная диагностика кластера `rac` в файл | 180–240 с |
| `netstat` | слушаются ли порты 1540/1541/1545 | 30 с |
| `services` | службы 1С и HASP | 30 с |
| `copy-log` | забрать журнал приложения с сервера | 60 с |
| `start-ras` | поднять `ras.exe --port=1545`, если он не запущен | 60 с |
| `cleanup` | убрать следы работы (см. ниже) | 120 с |
| `selftest`, `navtest` | **только локально и на стендах**: в фоновом сеансе WinForms виснет | — |

Примеры:

```powershell
.\tools\queue-send.ps1 -Command version -Server all
.\tools\queue-send.ps1 -Command digest  -Server s200 -TimeoutSec 300
.\tools\queue-send.ps1 -Command cleanup -Server s200 -TimeoutSec 120
```

## Признаки жизни

| Файл | Что значит |
|---|---|
| `drop\worker-all.txt`, `drop\worker-s200.txt` | «я жив», обновляется раз в минуту (внутри — время и имя сервера) |
| `drop\worker-all.log`, `drop\worker-s200.log` | журнал обработчика: когда запустился, какие задания выполнил, куда положил ответ |

Если heartbeat не обновлялся больше двух минут — окно закрыто, сеанс RDP разорван или обработчик
упал. Проверить: снова открыть окно на сервере.

## Убрать следы после работы

Обработчик **сам за собой не убирает** — для этого есть команда и отдельный файл:

1. **Через очередь** (пока окно открыто):
   ```powershell
   .\tools\queue-send.ps1 -Command cleanup -Server s200 -TimeoutSec 120
   ```
   Она удаляет: логи и дампы в `%TEMP%`, копии сборки и временные отчёты в
   `%TEMP%\1c-inspector-worker`, каталог `%ProgramData%\1C-License-Inspector` (там же
   `cluster.bin` — сохранённые логин/пароль кластера, если их вводили на сервере).
   Сама `Worker.exe` удалиться не может — она запущена, поэтому команда ставит **отложенную
   дочистку**: как только окно закроют, каталог исчезнет сам (в течение ~2 минут).
2. **Вручную, после закрытия окна** — `Убрать-следы.cmd` из папки проекта (запустить в RDP).
   Он закрывает окно обработчика по заголовку, чистит `%TEMP%` и `%ProgramData%\1C-License-Inspector`.
   Платформу 1С, `ras` и службы HASP не трогает — это не наше.

После закрытия окна и уборки на сервере не остаётся ничего: ни служб, ни задач, ни файлов.

## Если что-то не так

| Симптом | Причина и что делать |
|---|---|
| Нет ответа, heartbeat старый | окно обработчика закрыто / RDP-сеанс разорван — открыть окно заново |
| `НЕИЗВЕСТНАЯ КОМАНДА: cleanup` | окно запущено старой версией: закрыть окно, подменить `build\Worker.exe` (свежий лежит как `build\Worker-ready.exe`) и запустить `.cmd` снова |
| Два окна на одном сервере | они дерутся за очередь («то работает, то нет») — оставить одно, лишние закрыть |
| Задание «зависло» | смотреть `drop\worker-<сервер>.log`; `digest` на 2003 может идти 40–60 с из-за консоли 8.2 |
| Обработчик не стартует на 2003 | он на C# именно поэтому: PowerShell на 2003 — версии 1.0, без `try/catch` |
| Сборка пишет «Worker.exe занят» | окно открыто и держит файл; новая сборка останется как `build\Worker-ready.exe` — подменить после закрытия |

## Безопасность

- Обработчик выполняет только команды из белого списка — произвольную команду через него не передать.
- Пароль кластера, если его вводили, хранится на сервере в `cluster.bin` под DPAPI (только для того
  же пользователя на той же машине) и удаляется командой `cleanup`.
- Пока окно открыто, у агента есть доступ к серверу — закрывайте окно, когда работа закончена.
